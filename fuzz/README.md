# Fuzzing SoundFileTap

`tap_sf_open_memory` is the library's untrusted attack surface: it consumes
arbitrary bytes that claim to be a WAV file. `fuzz_wav.c` exercises it the way a
consumer would — open, stream-read to exhaustion, seek, read again, close — so
out-of-bounds accesses, overflow bugs, and allocation blowups surface under
AddressSanitizer/UBSan. The harness caps `max_total_bytes` at 64 MiB so an
allocation-bomb regression fails fast instead of OOMing the fuzzer.

## Real fuzzing (preferred) — Clang + libFuzzer

```sh
cmake -B build-fuzz -DTAP_SOUNDFILE_BUILD_FUZZERS=ON -DCMAKE_C_COMPILER=clang
cmake --build build-fuzz --target fuzz_wav
./build-fuzz/fuzz/fuzz_wav fuzz/corpus          # seed corpus bootstraps coverage
```

CI runs this continuously: `cflite_pr.yml` fuzzes the code changed by each PR
under ASan and UBSan (ClusterFuzzLite, code-change mode) and `cflite_batch.yml`
runs a longer scheduled campaign. `.clusterfuzzlite/` holds the OSS-Fuzz-style
build recipe both use.

## Standalone driver — any compiler, no fuzzer runtime

When the libFuzzer runtime is unavailable, `standalone_main.c` replays the
corpus and runs a bounded, deterministic mutation loop (fixed RNG seed, so runs
are reproducible). `ci.yml`'s fuzz-smoke job uses this.

```sh
cmake -B build-fuzz -DTAP_SOUNDFILE_BUILD_FUZZERS=ON
cmake --build build-fuzz --target fuzz_wav_standalone
./build-fuzz/fuzz/fuzz_wav_standalone fuzz/corpus/*
```

## Corpus

`fuzz/corpus/` holds tiny (<10 KB) seed files generated by
`tests/make_corpus.py` — valid WAVs across the supported shapes plus a few
near-valid mutants to park coverage next to the rejection paths. Regenerate
with `python3 tests/make_corpus.py`. **Add every crash reproduction found by
fuzzing to the corpus** (and a regression test to `tests/`) before fixing it.
